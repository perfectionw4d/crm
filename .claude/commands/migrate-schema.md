מבצע מיגרציה בטוחה של schema. הבקשה: $ARGUMENTS

⚠️ **שינוי schema הוא מסוכן** — קבצי JSON קיימים עלולים להישבר. עקוב **בדיוק** אחרי הצעדים:

### 1. גיבוי לפני הכל
```bash
# העתק את הקובץ הרלוונטי
cp data/<filename>.json data/<filename>.json.bak-$(date +%Y-%m-%d)
```

### 2. קרא והבן את הקובץ הקיים
- השתמש ב-Read כדי לראות 2-3 רשומות לדוגמה.
- ספור כמה רשומות יש (`node -e "console.log(require('./data/<filename>.json').length)"`).
- זהה אילו רשומות חסרות את השדה החדש.

### 3. כתוב סקריפט מיגרציה חד פעמי
- שמור ב-`scripts/migrate-<תיאור>.js` (צור תיקייה אם אין).
- הסקריפט צריך:
  - לקרוא את הקובץ.
  - לעבור על כל רשומה ולוודא שיש לה את השדה החדש (עם ברירת מחדל הגיונית).
  - לשמור גיבוי (אם עוד לא קיים).
  - לכתוב את הקובץ המעודכן.
- **תמיד** לעשות dry-run קודם — להדפיס כמה שינויים ייעשו לפני שכותבים.

### 4. עדכן את הקוד ב-server.js
- חפש כל מקום שקורא לשדה הקיים.
- הוסף ברירת מחדל גם בקוד (`record.newField || defaultValue`) — defensive programming.

### 5. עדכן את `CLAUDE.md` סעיף 7
הוסף את השדה החדש ל-schema המתועדת. שמור על פורמט זהה לשאר.

### 6. בדיקה
- הרץ `npm start` ובדוק שהשרת עולה בלי שגיאות.
- בדוק את ה-UI הרלוונטי בדפדפן.

### 7. אל תבצע commit אוטומטית
דווח למשתמש מה השתנה ובקש אישור לפני git commit.

### תזכורת

- אם השינוי גם דורש שינוי ב-Google sync (calendar/contacts) — עיין בסעיף 9 של CLAUDE.md.
